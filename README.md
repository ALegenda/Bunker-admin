# Bunker Studio

Каталог карточек для игроков, редактор правил и совместная вычитка. React + TypeScript, Fastify, PostgreSQL, MinIO/S3 и отдельный обработчик HTML → PDF.

Сайт: https://bunker-vdk.ru · Редактор: https://bunker-vdk.ru/admin

## Страницы

- `/qr` — страница с QR-кодом на `https://bunker-vdk.ru/` в стиле лендинга; доступна без входа и JavaScript, адаптирована для телефона и печати.
- `/` — публичный лендинг игры: знакомство с миром, ход партии, интерактивные роли, вопросы и вход в профиль. Готовые HTML и CSS отдаются первым ответом без ожидания JavaScript или сессии; React подключает интерактивность после загрузки.
- `/catalog` — опубликованный каталог: поиск по тексту, типу, времени, месту и нескольким тегам; ссылки на карточки.
- `/admin` — редактирование карточек, автосохранение, сравнение с опубликованным текстом и история.
- `/admin?view=publish` — подготовка сводки, проверка PDF, публикация версии.
- `/proposals` — предложения опытных игроков и их рассмотрение администратором.
- `/profile` — личный профиль вошедшего игрока: игровое имя, уровень, валюта, достижения и история начислений.
- `/users` — выдача и отзыв прав, просмотр профилей и ручные начисления.
- `/tips` — модерация советов к карточкам (для администратора).
- `/achievements` — каталог достижений: создание и редактирование названия, условия и числовой цели (для администратора).

Публичный каталог показывает исходную принятую редакцию, затем последний опубликованный выпуск. Правки черновика и принятые предложения становятся публичными только после публикации. Внутренние заметки и исходные метаданные не входят в API каталога.

## Локальный запуск

Нужны Node.js 22.12+, Docker Compose и Chrome. На текущем компьютере `.env` уже настроен, данные перенесены; **не заменяйте этот файл**.

```sh
npm ci
npm run infra:up
npm run db:seed
npm run build
npm start
```

При новой установке сначала скопируйте `.env.example` в `.env`, задайте индивидуальные пароли. `db:seed` не меняет существующий черновик. Интерфейс: http://localhost:4173/. После изменения фронтенда выполните `npm run build`; для разработки с обновлением без пересборки можно отдельно запустить `npm run dev:web`.

`db:seed` также применяет одноразовую миграцию тегов по правилам: [словарь и назначения карточкам](resources/rules-2026-05-24/TAGS.md). Она добавляет теги в черновик и опубликованный каталог независимо, сохраняет ручные теги и пропускает карточки с изменённым текстом. Отчёт пропусков и резервная копия сохраняются в БД; прежние выпуски не меняются.

Цвета окантовки и накладываемые эффекты добавляет следующая одноразовая миграция: [классификация и назначения](resources/rules-2026-05-24/METADATA.md). Эти группы доступны в фильтрах, редакторе и раскрываемом списке характеристик карточки.


Посетитель без сессии видит лендинг и каталог, даже локально. Старые ссылки `/?card=…` и фильтры автоматически перенаправляются на `/catalog` с сохранением параметров. Для работы с черновиком откройте `/admin` и нажмите «Открыть локальный редактор». Это явная сессия разработки на loopback; она сбрасывается при перезапуске сервера. Для размещения в интернете обязателен Telegram-вход; production-конфигурация запрещает локальный режим.

## Telegram и размещение

Бот: `@bunker_vdk_bot`. Домен покупать необязательно — можно использовать постоянный HTTPS-адрес хостинга. Реальный вход требует Client ID/Client Secret из Web Login в BotFather, Allowed URLs и числового Telegram ID первого администратора.

Размещение на Render, ресурсы, стоимость и автодеплой из `master` после CI:
[docs/render.md](docs/render.md), конфигурация `render.yaml`.
Общая настройка Telegram: [docs/production.md](docs/production.md).
Прежний VPS-деплой описан в [docs/deployment.md](docs/deployment.md) и отключён
переменной `DEPLOY_ENABLED=false`; его файлы сохранены для восстановления.

## Роли

| Роль | Возможности |
|---|---|
| Гость | Каталог, фильтры, опубликованные PDF, сводки и одобренные советы |
| Авторизованный игрок | Всё доступное гостю, личный профиль и настройка игрового имени |
| Опытный игрок | Возможности игрока, предложения описаний и новых карточек, отзыв до рассмотрения, отправка советов и чтение советов до публикации |
| Администратор | Черновик, изображения, PDF, публикация, рассмотрение предложений, модерация советов, управление доступом и игровыми показателями |

Права проверяются сервером на каждом запросе. Сессии хранятся в PostgreSQL; браузер получает HttpOnly cookie. Изменение роли отзывает сессии. Последний администратор защищён от случайного отключения.

## Профили и советы

Кнопка «Войти» открывает `/profile`; после Telegram-входа игрок видит свой профиль.
Игровое имя (до 80 символов) используется в советах и предложениях и не сбрасывается
при повторном входе. Чужие профили доступны только администратору.

Начальные показатели: уровень 1, баланс 0, без достижений. В разделе «Игроки»
администратор открывает «Профиль и начисления», указывает итоговый уровень и баланс,
выбирает достижения из каталога, задаёт их прогресс или убирает их и обязательно пишет причину. Изменения сохраняются
одной операцией с проверкой версии профиля; игрок видит последние 100 операций в истории.
В разделе «Достижения» администратор создаёт название, условие и цель: например,
«Ветеран бункера», «Сыграть 100 игр», цель 100. В профиле игрока добавляет достижение
из каталога и выставляет счётчик от 0 до цели. При 37/100 игрок видит «В процессе»
и полосу прогресса, при 100/100 — «Получено» и дату. В число полученных наград входят
только завершённые. Уменьшение счётчика ниже цели возвращает статус «В процессе»;
повторное сохранение завершённого достижения не меняет дату получения.

Каталог служит шаблоном для назначения. Редактирование шаблона не меняет уже
назначенные игрокам достижения: они сохраняют название, описание и цель на момент
назначения. Старые награды без счётчика отображаются как завершённые 1/1.
Изменение каждого счётчика видно в истории профиля. Игрок не может менять прогресс.
Автоматического подсчёта игр, начисления, покупок и переводов между игроками пока нет.

Советы — обычный текст до 3000 символов, без веток обсуждения. Писать могут опытные
игроки и администраторы после Telegram-входа. Новый совет видят все опытные игроки
и администраторы; обычные игроки и гости получают только опубликованные советы.
Администратор публикует или отклоняет совет прямо у карточки либо в разделе «Советы».
Он также может снять совет с публикации или повторно одобрить отклонённый.
Отклонённый совет и комментарий модератора видят только автор (с ролью опытного игрока)
и администратор. Советы публикуются независимо от выпуска правил.

Миграции `004_profiles_tips.sql` и `005_achievement_catalog.sql` выполняются автоматически при запуске API, как и остальные миграции. Локальный редактор без Telegram-аккаунта не имеет личного профиля;
для проверки ролей на отдельной копии используйте `backend/tests/browser-fixture.ts`.

## Архитектура

- `frontend/src/components/` — отдельные экраны и формы React.
- `frontend/src/useEditor.ts` — очередь сохранения отдельных карточек и браузерные резервные копии.
- `shared/` — общие схемы, типы API, сравнение версий и составление сводки.
- `backend/http/` — HTTP-маршруты, проверка сессий, прав и CSRF.
- `backend/services/` — сценарии карточек, каталога, предложений, публикаций, Telegram, S3 и PDF.
- `backend/db/` — миграции и транзакции.
- `resources/print/` и `resources/fonts/` — оформление PDF и шрифты.
- `public/` — старый интерфейс и исходные материалы импорта; веб-сервер теперь выдаёт только собранный `web-dist/`.

## Проверки и резервная копия

```sh
npm run typecheck
npm test
npm run build
npm run backup
```

Тесты используют отдельные временные схемы PostgreSQL и не меняют рабочие карточки. Проверяются версии карточек, публикация, очередь PDF, Telegram-подписи, CSRF, роли, предложения и отзыв доступа. Браузерную проверку на отдельной копии можно запустить через `node --import tsx backend/tests/browser-fixture.ts`; это отдельный процесс на loopback-порту 4174, тестовые маршруты не входят в рабочий сервер.

Backup сохраняет БД и связанные объекты S3 с контрольными суммами в `tmp/backups/<дата>`. Порядок восстановления и настройки хранения описаны в инструкции production. Не запускайте `docker compose down -v`, если нужно сохранить данные.

### Диагностика долгой сборки PDF

API и worker пишут JSON-события с `component: "pdf"`, временем `timestamp` и
идентификатором `jobId`. У каждой попытки worker есть отдельный `attemptId` и номер
`attempt`. После обновления приложения логи следующей сборки можно получить так:

```sh
docker compose -f compose.yaml -f compose.production.yaml --profile app logs --since 30m --timestamps api worker
```

Найдите `job.requested` или `job.started` и отфильтруйте вывод по его `jobId`.
`ageSinceQueuedMs` — возраст задания при запуске (при повторной попытке включает
предыдущие попытки); `elapsedMs` — время с начала текущей попытки; `durationMs` —
длительность отдельного этапа. Вложенные этапы перекрываются: складывать их время
с временем родительского этапа не нужно.

Основные этапы: `html.render`, `image.lookup`, `image.download`, `image.convert`,
`pdf.render`, `chromium.print`, `pdf.validate`, `pdf.cleanup`, `upload.*`,
`job.save_result`. Для изображений записываются `assetId`, размеры в байтах и
прогресс обработки. Долгие этапы каждые 15 секунд пишут `.waiting`. События
`chromium.spawned`, `chromium.output_detected`, `chromium.exit` и
`chromium.timeout` помогают отличить запуск браузера от ожидания готового файла.
`job.ready` содержит итоговое время попытки, число страниц и размер PDF.
Ошибки фиксируются в `.failed`; проблемы продления аренды задания — в
`job.lease_renewal_failed`. Тексты карточек, HTML и содержимое картинок в логи не пишутся.
