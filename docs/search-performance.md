# Поиск: быстродействие и опечатки

Проверка 20.09.2026 на копии опубликованного каталога: **329 карточек**.
Исходная версия: `b79b292`. Правки затрагивают каталог и поиск в редакторе.

## Что тормозило

При каждом изменении поля поиска `matchesCard` заново собирал поисковый текст всех
карточек, извлекал текст из rich text и многократно нормализовал характеристики.
Семь групп фильтров снова обходили весь каталог. React перерисовывал все карточки,
включая скрытые группы характеристик. При пустом запросе в DOM было 329 карточек
и 15 366 элементов. Кроме того, публичный каталог загружал Tiptap через импорты
формы карточки и формы предложения.

## Изменения

- Поисковые документы и нормализованные характеристики готовятся один раз на
  неизменяемый объект карточки/характеристик. `WeakMap` не удерживает старые версии
  черновика. Изменение карточки, её удаление или добавление обновляет индекс.
- Вычисление выдачи отделено от ввода через `useDeferredValue`; список и фильтры
  мемоизированы. Превью описания использует уже подготовленный текст.
- Первоначально выводятся 24 карточки. При приближении к концу списка
  `IntersectionObserver` автоматически добавляет следующие 24, с запасом 400 px.
  В каталоге отслеживается прокрутка страницы, в редакторе — отдельного списка. Поиск и счётчик всегда охватывают весь каталог. При смене состава/порядка
  результатов окно сбрасывается; обычное редактирование карточки с теми же
  результатами не сбрасывает раскрытый список.
- Редактор предложения загружается только при открытии формы. Вынесенный список
  типов больше не подтягивает форму карточки в каталог. Отложенный JS редактора:
  около 399 КБ, 125 КБ gzip в проверенной сборке.

## Правила поиска

Проверяются название, описание, условия использования и характеристики.
Регистр, лишние пробелы и различие `е/ё` не влияют на совпадение. Несколько слов
могут находиться в разных местах и идти в другом порядке; нужны все слова.
Старые названия характеристик и цветовые алиасы сохранены.

Для слов из четырёх и более букв допускается одна вставка, пропуск, замена или
перестановка соседних букв: `банкр`, `бонкир`, `банкри` находят «Банкир».
Исправление сравнивается с целым словом, а точные части слова по-прежнему работают.
Короткие запросы и числа не исправляются. Синонимы, морфология, неверная раскладка
и две ошибки в одном слове пока не поддерживаются.

Сначала идут точные совпадения: полное название, часть названия, все слова в
названии, затем описание/характеристики. Далее — совпадения с опечатками, также
с приоритетом названия. При одинаковой релевантности сохраняется порядок каталога.
Число дополнительных результатов показывается в строке «с учётом опечаток».
Фильтры типа и характеристик остаются строгими для всех результатов.

## Измерения

| Проверка | До | После |
| --- | ---: | ---: |
| Поиск `лек`, медиана в Node, прогретый код | 21,40 мс | 0,11 мс |
| Пересчёт семи групп фильтров, медиана в Node | 10,69 мс | 0,17 мс |
| Реакция на ввод в Chrome, медиана 16 изменений | 199,7 мс | 18,9 мс |
| Самая долгая реакция в этом сценарии | 718,8 мс | 38,5 мс |
| Элементов DOM при пустом запросе | 15 366 | 1 452 |
| Карточек в начальном DOM | 329 | 24 |

Первичная подготовка индекса в Node занимает около 28 мс; она не входит в время
повторного поиска. С опечатками поиск занимал примерно 0,18–0,35 мс.

Браузерная проверка использовала production-сборку, headless Chrome на этом Mac,
экран 390×844 и замедление CPU в 6 раз. API возвращал один и тот же сохранённый
каталог через локальный HTTP-сервер; картинки не загружались. Последовательность:
`л → ле → лек → лека → лекар → лекарс → лекарст → лекарство → пусто → б → ба → бан
→ банк → банкр → банкри → банкир`. Каждое значение заменяло содержимое поля через
CDP `Input.insertText` (очистка — Backspace).

Время реакции измерено от события `input` до второго `requestAnimationFrame`.
Это лабораторный показатель отзывчивости, **не полевой INP**, не оценка сети и не
замер на реальном Android/iPhone. Отложенная выдача может завершиться после
измеренного кадра. Её итоговые значения и отсутствие зависшего состояния отдельно
проверены после ввода, в том числе при быстрой смене запросов.

## Повторение и проверки

Сохранить публичный ответ и измерить вычисление поиска:

```sh
curl --fail https://bunker-vdk.ru/api/catalog -o tmp/search-catalog.json
node --import tsx scripts/benchmark-search.ts tmp/search-catalog.json
```

Скрипт печатает время первичного индекса, медиану и p95 для каждого запроса
(5 прогревочных + 100 измеренных запусков). Он не измеряет рендеринг React.

Пройдены TypeScript, production-сборка и 59 тестов: весь набор фронтенда,
общая модель, чтение JSON, rich text и нормализация характеристик. Полный набор
интеграционных тестов PostgreSQL/S3/PDF для этих правок не запускался.

Дополнительно проверены в браузере: автоматическое расширение выдачи при скролле, сохранение
раскрытого списка после закрытия карточки, открытие карточки вне первой порции
по прямой ссылке, фильтры типа и опасной личности, URL, быстрый ввод с опечаткой,
отсутствие загрузки Tiptap у гостя и поиск/выбор карточки в редакторе.
