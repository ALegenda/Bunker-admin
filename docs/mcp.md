# MCP энциклопедии Бункера

Публичный MCP даёт ChatGPT и другим совместимым клиентам доступ к опубликованным карточкам и общим правилам Бункера. Отдельный административный режим также работает с редакционной очередью. Модель клиента вычитывает текст, объясняет правила и анализирует взаимодействия карточек. Сам сервер не вызывает LLM и не требует ключа OpenAI или другого поставщика.

Сервер использует официальный TypeScript SDK. Для игроков работает **HTTPS Streamable HTTP** по адресу `https://bunker-vdk.ru/mcp`; вход, SSH, установка Node и ключи API не требуются. Для доверенных локальных клиентов сохранён транспорт **stdio**. Реализация: `backend/mcp/`, HTTP-маршрут: `backend/http/routes/mcp.ts`.

## Подключение игрока в ChatGPT

Адрес сервера: **`https://bunker-vdk.ru/mcp`**. Авторизация: **No authentication**.

1. Откройте ChatGPT в браузере и перейдите в раздел **Plugins**.
2. Нажмите **+ → Add custom MCP server**.
3. Укажите название «Бункер», адрес выше и **No authentication**.
4. Подтвердите предупреждение ChatGPT и нажмите **Create as a plugin**.
5. Установите созданный плагин из личного списка Plugins. В новом чате введите `@`, выберите «Бункер» и задайте вопрос о правилах.

Например: «Найди правила лечения и объясни, как работает Лекарь. Приведи цитаты и ссылки на карточки».

Сервер доступен любому игроку. Возможность добавить пользовательский MCP в ChatGPT зависит от настроек аккаунта и ограничений workspace; сервер не может изменить эти ограничения. Текущий порядок подключения описан в [OpenAI Docs](https://developers.openai.com/api/docs/guides/custom-mcp-server).

HTTP MCP предоставляет пять инструментов чтения: обзор, поиск, полную карточку, пакет карточек и сравнение взаимодействий. Он читает текущую опубликованную редакцию сайта; черновики, личные данные, предложения и административные операции через него недоступны, в том числе при передаче браузерной сессии или `source=draft`.

Запросы не создают сессий MCP и не требуют cookie или CSRF-токена. Ресурсы и шаблоны также доступны совместимым клиентам. Лимит тела POST — 64 КиБ, действует обычное ограничение частоты запросов API. Host проверяется сервером; запросы без Origin разрешены, а браузерный Origin должен соответствовать сайту, `https://chatgpt.com` или `https://chat.openai.com`. Для локальной разработки также разрешён origin loopback-сервера. POST возвращает JSON; GET и DELETE возвращают 405, поскольку отдельный поток уведомлений и завершение сессии в этом режиме не нужны.

## Подключение по URL в Codex

Конфигурация `.codex/config.toml` входит в репозиторий:

```toml
[mcp_servers.bunker]
url = "https://bunker-vdk.ru/mcp"
startup_timeout_sec = 45
tool_timeout_sec = 60
```

Для других проектов можно выполнить `codex mcp add bunker --url https://bunker-vdk.ru/mcp`. После изменения конфигурации перезапустите MCP в настройках клиента. [OpenAI Docs — MCP](https://learn.chatgpt.com/docs/extend/mcp).

## Локальный stdio: сборка и подключение

```sh
npm ci
npm run build:mcp
```

Обычная `npm run build` также собирает MCP. Пример конфигурации клиента, который использует `mcpServers`:

```json
{
  "mcpServers": {
    "bunker": {
      "command": "node",
      "args": ["/ABSOLUTE/PATH/Bunker-admin/scripts/mcp.mjs"],
      "env": {
        "BUNKER_MCP_MODE": "public",
        "BUNKER_MCP_ORIGIN": "https://bunker-vdk.ru"
      }
    }
  }
}
```

Подставьте абсолютный путь к репозиторию. Если клиент не находит Node, укажите абсолютный путь к нему в `command`. Для ручного запуска есть `npm run start:mcp`, но в конфигурации клиента вызывайте **node напрямую**: служебный вывод npm в stdout мешает протоколу. Процесс ждёт JSON-RPC-сообщения в stdin; браузерной страницы у него нет.

## Режимы доступа stdio

| Настройка окружения клиента | Значение |
|---|---|
| `BUNKER_MCP_MODE` | `public` по умолчанию; `editor` для локальной БД |
| `BUNKER_MCP_ORIGIN` | Адрес без пути, query и пароля. В public по умолчанию `https://bunker-vdk.ru`; в editor — `PUBLIC_ORIGIN` приложения |
| `BUNKER_MCP_AUTHOR_ID` | Необязательный UUID существующего пользователя БД с ролью `trusted` или `admin`; включает отправку предложений и чтение их статусов только в editor |

**Public:** читает `/api/catalog` указанного сайта без сессии, cookie и секретов. Доступна только опубликованная редакция. Локальная БД, `.env`, MinIO и запущенный API не нужны, если читается рабочий сайт. Для локального API разрешён origin `http://127.0.0.1:4173`. HTTP вне loopback запрещён; перенаправления не выполняются. Каждый вызов заново читает текущий каталог, ошибки и недоступность возвращаются клиенту.

**Editor:** читает существующую PostgreSQL из конфигурации приложения. Launcher переходит в каталог репозитория, затем сервер загружает его `.env`. MCP-настройки выше задаются в окружении **клиента**, до запуска процесса. Нужны готовая БД и выполненные обычным запуском приложения миграции; MCP не мигрирует и не импортирует данные при старте.

Для editor измените `env` в примере:

```json
{
  "BUNKER_MCP_MODE": "editor",
  "BUNKER_MCP_AUTHOR_ID": "UUID_СУЩЕСТВУЮЩЕГО_ЭКСПЕРТА_ИЛИ_АДМИНИСТРАТОРА"
}
```

Без `BUNKER_MCP_AUTHOR_ID` editor позволяет читать черновик и историю, но инструментов отправки предложений нет. UUID можно узнать на доверенном сервере: `SELECT id, display_name, role FROM users WHERE NOT disabled AND role IN ('trusted','admin');`. Не передавайте агенту Telegram-сессии или содержимое `.env`.

Editor — доверенный локальный процесс с доступом к БД. Подключайте его к агенту, которому разрешено читать неопубликованные тексты. Для доступа к production-БД его можно запускать на доверенном сервере через SSH stdio; не открывайте процесс как публичный HTTP endpoint. Выбор editor делается окружением клиента, агент не может включить его аргументом инструмента.

## Административный stdio на Hoster.kz

MCP и launcher включены в production-образ приложения. SSH-клиент запускает отдельный процесс внутри действующего API-контейнера; он использует уже настроенное окружение production и актуальную БД:

```sh
ssh -T -o BatchMode=yes -o StrictHostKeyChecking=yes \
  -o IdentitiesOnly=yes -o UserKnownHostsFile="$BUNKER_KNOWN_HOSTS" \
  -i "$BUNKER_SSH_KEY" root@89.126.194.117 \
  'cd /opt/bunker-production && docker compose exec -T -e BUNKER_MCP_MODE=editor api node scripts/mcp.mjs'
```

В MCP-клиенте задайте `command: "ssh"`, а эти флаги, сервер и удалённую команду — отдельными элементами `args`. Используйте существующий доверенный SSH-доступ из [инструкции production](deployment.md); секреты приложения в конфигурацию клиента не переносятся. Для включения предложений добавьте в удалённый `docker compose exec` флаг `-e BUNKER_MCP_AUTHOR_ID=<UUID разрешённого автора>`.

Игроки подключаются к публичному `https://bunker-vdk.ru/mcp`. SSH нужен только для отдельного доверенного editor-доступа администратора. Публичное чтение через локальный stdio-процесс также сохранено.

Штатная выкладка проверяет MCP официальным клиентом внутри контейнера: чтение published и draft через stdio, поиск, карточку, ресурс, шаблон вычитки, сравнение и историю. Затем отдельно проверяет HTTP-маршрут без авторизации: пять инструментов чтения, опубликованную карточку и запрет draft. Проверка только читает данные. Ошибка MCP запускает обычный откат образов API и worker до фиксации нового активного релиза.

## HTTP-клиент из терминала или чата Codex

`scripts/mcp-client.mjs` использует официальный SDK и публичный HTTPS endpoint. Нужны только `npm ci` и Node.js; доступ к серверу и его БД настраивать не требуется.

```sh
npm run mcp:check
node scripts/mcp-client.mjs tools
node scripts/mcp-client.mjs call encyclopedia_overview
node scripts/mcp-client.mjs call search_cards '{"query":"Лекарь","limit":3}'
node scripts/mcp-client.mjs call read_card '{"cardId":"ID_ИЗ_ПОИСКА"}'
node scripts/mcp-client.mjs resources
node scripts/mcp-client.mjs templates
node scripts/mcp-client.mjs read bunker://catalog/published
node scripts/mcp-client.mjs prompts
node scripts/mcp-client.mjs prompt explain_rule '{"question":"Как снять заражение?"}'
```

`call` и `prompt` принимают JSON-объект либо `--stdin`. Ответ содержит исходные `content`, `structuredContent` и `isError`. Результаты — JSON в stdout; при ошибке инструмента или подключения код выхода равен `1`, диагностика клиента идёт в stderr. Для локальной проверки задайте `BUNKER_MCP_URL=http://127.0.0.1:4173/mcp`.

JavaScript API: `withPublicMcp(action, url?)` открывает HTTP-подключение, передаёт официальный `Client` в `action` и закрывает его после вызова.

## Инструменты

| Инструмент | Назначение |
|---|---|
| `encyclopedia_overview` | Редакция, размер каталога и словарь типов, тегов, эффектов, времени и места |
| `search_cards` | Поиск по названиям, описаниям и атрибутам; фильтры и страницы до 50 результатов |
| `read_card` | Полный текст, исходное форматирование, характеристики, URL и `contentHash` |
| `get_review_batch` | До 10 полных карточек за раз и проверочный список для вычитки |
| `compare_cards` | 2–10 карточек одной редакции для проверки взаимодействий и терминологии |
| `compare_draft` | В editor: разница опубликованной карточки и черновика, включая добавление и удаление |
| `card_history` | В editor: история по опубликованным выпускам |
| `submit_card_proposal` | При настроенном авторе: предложить описание и необязательное название существующей опубликованной карточки |
| `list_my_proposals` | При настроенном авторе: статусы и замечания к его предложениям |

Для чтения `source` по умолчанию `published`; `draft` доступен только в editor. Поиск текстовый: все слова запроса обязательны, регистр и ё/е не влияют на поиск. Для вопроса на естественном языке агент сначала выбирает ключевые слова и делает несколько запросов. Векторного поиска здесь нет. Все выбранные теги обязательны; время и место фильтруют по наличию значения, поэтому карточки с обоими временем/местом тоже находятся.

Результат поиска содержит выдержку до 500 символов с признаком `truncated`. Для ответа и цитат агент читает полный текст через `read_card`. `description` сохраняет принятую структуру rich text, `text` даёт обычный текст для анализа. Внутренние заметки, исходные приватные метаданные, пользователи и сессии в контекст не входят.

Для обхода каталога используйте `nextOffset`, те же фильтры и `expectedSnapshotHash`, равный `snapshotHash` предыдущей страницы. Если редакция изменилась, сервер останавливает обход: нужно начать с первой страницы, чтобы не смешать версии и не пропустить карточки. `snapshotHash` обозначает содержимое редакции, а не ID выпуска.

## Ресурсы и готовые задачи

Ресурсы JSON:

- `bunker://catalog/published` — сведения и словарь опубликованной редакции.
- `bunker://catalog/draft` — аналогичный ресурс editor.
- `bunker://cards/{source}/{cardId}` — полная карточка; её корректно закодированный URI возвращается в `resourceUri`.

Шаблоны запросов MCP:

- `proofread_cards(cardIds, source?)` — идентификаторы через запятую, до 10 карточек. Проверяет язык, термины, условия, ограничения и соответствие атрибутам; отделяет редактуру от изменения механики.
- `explain_rule(question)` — ответ игроку по опубликованной редакции с цитатами и ссылками.
- `check_interactions(cardIds, situation)` — взаимодействие 2–10 опубликованных карточек и неразрешённые вопросы к автору.

Шаблоны и инструменты дают модели источники и инструкции для анализа. Текстовый MCP-сервер сам не определяет правильность правил. Неоднозначность оформляется вопросом автору, а выводы модели подкрепляются карточками и ссылками. Содержимое карточек и комментариев явно обозначено как недоверенные данные.

Примеры задач агенту:

> Вычитай все умения по пять карточек: орфография, ясность целей, ограничения, условия применения. Для каждой проблемы покажи цитату и предложенную редакцию. Не меняй механику без вопроса автору.

> Объясни, как взаимодействуют Лекарь и заражение. Найди общие правила, процитируй основания и дай ссылки на карточки.

> Сравни черновик карточки с опубликованным текстом и проверь, не появилось ли новое исключение.

## Предложения и защита от устаревших правок

Агент сначала вызывает `read_card` с `source=published`, затем передаёт `contentHash` как `expectedHash` в `submit_card_proposal` вместе с новым описанием и причиной. Сервер проверяет хеш, затем повторно сверяет базу под блокировкой строки внутри транзакции создания предложения. Изменение публикации между чтением и записью останавливает отправку.

Карточки только из черновика через этот инструмент не предлагаются. Для вычитки draft агент готовит отчёт; для сохранения предложения он должен отдельно сверить published и подготовить правку на его основе.

Предложение получает метку `[MCP]` в причине, реального настроенного автора и обычную запись аудита. Оно видно в `/proposals`. Актуальная роль, блокировка и предел в 30 ожидающих предложений проверяются существующим сервисом при каждой отправке. Повторный вызов отправки может создать отдельное предложение; перед повторением после неопределённого результата проверьте `list_my_proposals`.

MCP не содержит инструментов принятия, прямого сохранения карточки или публикации. Автор рассматривает предложение в интерфейсе; принятие меняет черновик с обычной защитой от конфликтов. Публичный текст меняется только после обычной публикации выпуска.

## Проверки

```sh
npm run typecheck
npm run build:mcp
node --import tsx --test backend/tests/mcp.test.ts
node --import tsx --test backend/tests/mcp-http.test.ts
node --import tsx --test backend/tests/mcp-database.test.ts
```

Первый набор проверяет официальный MCP-клиент, реальные сообщения протокола, ресурсы, шаблоны, пагинацию, запрет черновика в public, скрытие приватных данных, ошибки и отдельный процесс stdio без credentials БД. HTTP-набор проверяет реальное подключение официального клиента, CLI, анонимное чтение, изоляцию editor, Origin, Host, лимит тела и сохранение защиты административного API. Набор БД использует временную схему PostgreSQL: авторство, права, устаревшие базы, очереди и применение предложения только в draft. Для него нужна запущенная локальная PostgreSQL. Все наборы входят в `npm test`.

Если переменные БД заданы только в локальном `.env`, для полного прогона всех тестов приложения загрузите его до старта: `NODE_OPTIONS='--import=dotenv/config' npm test`. В CI переменные уже заданы окружением.

Основа протокола и правила stdout: [официальная инструкция MCP](https://modelcontextprotocol.io/docs/develop/build-server), [TypeScript SDK](https://github.com/modelcontextprotocol/typescript-sdk).
