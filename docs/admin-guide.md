# Руководство автора

## Локальный запуск

1. Скопируйте `.env.example` в `.env` и проверьте `DATABASE_URL`.
2. Запустите Postgres через Docker Compose.
3. Выполните `npm run db:migrate` и `npm run db:seed`.
4. Откройте `/admin`.

## Авторизация

Публичная энциклопедия доступна без входа. Автор и эксперты входят через Telegram.

Локальный seed создает администратора из:

- `ADMIN_TELEGRAM_ID`
- `ADMIN_DISPLAY_NAME`

Эксперты получают invite link. После входа через Telegram invite связывается с Telegram account id эксперта.

## Редакционный workflow

1. Последняя опубликованная версия отображается в публичном справочнике.
2. Для правок создается новый черновик на основе published-версии.
3. Автор работает внутри черновика: слева дерево контента, по центру TipTap-редактор, справа инспектор атрибутов, источников и предложений.
4. Карточки и разделы правил редактируются в черновике.
5. Принятые экспертские предложения применяются только к черновику. Принятие предложения не означает публикацию.
6. Перед публикацией автор смотрит diff, changelog и ошибки валидации.
7. После публикации версия становится immutable, а публичный сайт переключается на нее.

Админка доступна по `/admin`, вход по `/login`.

Основные страницы:

- `/admin` - рабочий стол версии: активный черновик, опубликованная версия, изменения, предложения, быстрые действия.
- `/admin/workspace` - основной редактор активного черновика с деревом правил и карточек.
- `/admin/versions` - создание черновика, preview, сравнение и публикация.
- `/admin/proposals` - inbox предложений экспертов, diff, комментарии и применение в draft.
- `/admin/invites` - создание и отзыв инвайтов.
- `/admin/data` - импорт и экспорт актуальных данных через JSON.
- `/admin/pdf` - генерация PDF для выбранной версии.

## Рабочее место автора

Основной экран автора должен быть оптимизирован под регулярную редакционную работу:

- Левая колонка: дерево контента с разделами правил, умениями, припасами и мертвыми бонусами.
- Центральная область: TipTap-редактор выбранного раздела или карточки.
- Правая колонка: инспектор. Для карточки он показывает тип, время активации, частоту, место применения, теги, источник, связанные предложения и историю.
- Верхняя панель: активная версия, статус сохранения, preview, diff, публикация.

В интерфейсе не использовать технические формулировки вроде `CardRevision` и `ChangeSet`. Автор должен видеть человеческие названия: карточка, раздел, черновик, опубликованная версия, предложение, история изменений.

## Работа с предложениями

Эксперт принимает ссылку `/invite/<token>`, входит через Telegram и работает в экспертском режиме энциклопедии. Он читает актуальные правила и карточки, а предложение создает прямо из карточки или раздела.

Предложение проходит статусы:

- `draft` - эксперт начал, но не отправил.
- `submitted` - предложение отправлено автору.
- `in_review` - автор рассматривает.
- `needs_changes` - автор просит уточнить.
- `accepted` - автор согласен с изменением по смыслу.
- `applied_to_draft` - изменение применено к активному черновику.
- `published` - изменение вошло в опубликованную версию.
- `rejected` - отклонено с причиной.

Автор видит diff предложения относительно базовой версии. Если текст уже изменился в черновике, интерфейс должен показать конфликт и потребовать ручного применения.

## Публикация

Перед публикацией автор должен видеть:

- список добавленных, измененных и удаленных карточек;
- список измененных разделов правил;
- предложения экспертов, включенные в версию;
- ошибки валидации;
- итоговый changelog, который можно показать игрокам;
- ссылку preview публичного справочника.

Публикация запрещена, если в черновике есть конфликтующие предложения или критичные ошибки валидации.

## Импорт и экспорт JSON

JSON-обмен нужен, чтобы автор мог выгрузить актуальную базу правил, отправить ее в LLM для консультации и при необходимости импортировать проверенный patch обратно.

Экспорт доступен в `/admin/data`:

- `llm_context` - рекомендуемый режим для LLM. Включает правила, карточки, атрибуты, теги, источники и changelog. Не включает пользователей, Telegram ids, инвайты, сессии и токены.
- `full_version` - полный снимок выбранной версии без auth-данных.
- `cards_only` - карточки в формате, близком к `docs/cards.json`.

Импорт:

1. Загрузить JSON.
2. Запустить dry-run.
3. Проверить diff, ошибки и предупреждения.
4. Создать новый draft из `full_version` или применить `llm_patch` к активному draft.

Импорт никогда не меняет опубликованную версию напрямую. Любые импортированные правки проходят через черновик и обычный экран публикации.

## PDF

Smoke-генерация запускается командой `npm run pdf:smoke`. Она берет последнюю published-версию из БД, создает HTML из структурированных данных, рендерит PDF через Playwright, сохраняет файл в persistent volume `generated-pdfs` и пишет `GeneratedPdf` metadata.

HTML-шаблон должен максимально повторять существующий PDF-документ по структуре и визуальному стилю.

Если после установки зависимостей Playwright пишет, что executable не найден, выполните:

```bash
npm run postinstall:browsers
```
